# 前瞻阅读与角色出场总表

目标：防止"后文才揭示身份的角色被提前绑定错误身份"——这类错误一旦进入设定图和分镜，
返工成本是整页作废＋重roll设定图，且很难在当章内发现。

## 血泪案例（假设性示例）

某书第 N 章结尾，一位"蓝发持杖的少女"救场。制作时只读到前十章，把她与前期已登场、
外形描述高度相似的另一角色（同色系发型＋同类法杖＋同款裙装）绑定成同一人。
继续往后读才发现：救场的是**另一位**尚未正式介绍的角色；而"被绑定的那位"此时
还没有获得力量，要到几章之后才初次登场觉醒。结果：高潮页整页作废重roll，两张设定图重做。
教训：外形相似 ≠ 同一人；点名文本出现之前，一切相似角色只能是"待确认"。

## 规则

1. **做第 N 章前至少读到第 N+20 章**；首次开工普查前 30 章。
2. **身份以首次点名章节为准**。点名前，无名角色一律挂"待确认"标签，不绑定任何已知名。
3. 外形相似 ≠ 同一人。同一"配色+道具"描述可属于多个角色；绑定前必须找到点名文本。
4. 亲属代称（妹妹/少年/父亲）点名前单独按代称建档，点名后合并档案。

## 角色出场总表模板（01-设定/角色出场总表.md）

```markdown
# 角色出场总表（前30章普查版）
> 维护规则：每开新章节制作前，先向后多读 20 章，核对出场角色；
> 新角色先补设定图再进分镜。本表随制作持续推进更新。

## 一、角色档案卡
| 代号 | 身份（含升级/变身形态） | 首次登场 | 设定图状态 |
|---|---|---|---|
| 角色甲 | 主角；第N章起获得形态B＝"形态名·X" | 第1章 | 常规形态✅ / 形态B❌ |
| "妹妹"（代称） | 第M章点名＝李四；点名前按代称建档 | 第2章 | ❌ |

## 二、逐章出场矩阵
| 章 | 张三 | 妹妹 | … | 备注 |
|---|---|---|---|---|
| 1 | ✅ |  |  | |
| 2 | ✅ | ✅(代称) |  | "神秘救场者"＝待确认（后文点名后合并档案） |

## 三、设定图补录计划
| 优先级 | 角色/资产 | 用途 | 状态 |
|---|---|---|---|
| P0 | 形态B设定图（当前章急用） | 当前章高潮页 | 本次生成 |
| P1 | 新配角设定图（未来3章内） | 第N章 | 制作前补 |
| P2 | 远期提及角色 | 远期 | 后续 |
```

## 自动扫描方法

已知角色名清单固定后，用脚本按章节切分原文（`第X章`正则），逐章统计每个角色名
（含别名/变身名，注意代称）是否出现，输出 ✅ 矩阵；再人工补注"代称/待确认"类。
关键词注意一语多关（如角色名与普通词同形时人工复核）。

## 与其他阶段的衔接

- S1：普查完成后先建总表，再写设定总表——设定总表的角色卡以点名后的身份为准。
- S2：按补录计划生成设定图，档案卡同步更新 ✅/❌。
- S3：拆分镜前核对总表，角色引用写设定图 ID。
- S4：发现画面角色疑似绑错身份时，回总表核实，宁可整页重roll。
